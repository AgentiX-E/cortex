# Test dependencies for the `tools/` Python scripts.
#
# These scripts are not incidental: `push-via-api.py` is the only path that can
# publish to GitHub from this sandbox, `dispatch-b7-ab.py` is the only path that
# can start a benchmark run, and `pin-github-hosts.py` is what makes either work
# at all. All three were untested and absent from CI until this file existed,
# which is how a defect that silently stops the pin from applying survived.
#
# Version ranges rather than pins: this is a test-only toolchain for a repository
# whose runtime is Node, and an exact pin here would need a bot to keep it fresh.
# The runner image supplies the interpreter; only the test framework is installed.
pytest>=8,<10

# Not a test dependency: `fetch-artifact.py` imports it at module scope, so the
# script cannot even print its usage without it. Its absence on a clean runner is
# what the first CI run of `pnpm check` failed on -- three usage tests got exit 1
# and an empty stdout, because the import raised before `main` was reached, and
# the subprocess harness captures stderr without printing it. The tool works
# locally only because the development environment already had `requests`.
#
# Every other tool in this directory uses the standard library alone, so this is
# the complete set.
requests>=2.31,<3

# Added with `test_workflow_yaml.py`, and it is the same class of omission the
# paragraph above records: that guard PARSES the workflow files rather than grepping
# them, because a quoting error inside a single-quoted YAML scalar is invisible to a
# text search -- and that is what refused a dispatch with a message naming the wrong
# cause. It raises `AssertionError` rather than skipping when the import fails, on the
# argument that a control which skips is a control that is not there, so an undeclared
# dependency here fails the gate on a clean runner instead of passing quietly.
PyYAML>=6,<7
